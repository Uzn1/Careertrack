# PRD 구현 단계

기준: 저장소 루트 `PRD.md`. 사용자 지정 기술은 Nuxt 4·Vue·TypeScript·Tailwind CSS, 데이터 저장은 Supabase, 배포는 Vercel이다. 사용자의 추가 승인에 따라 2~5단계는 중간 확인 없이 순서대로 구현·검증한다. 최종 확인 후 해당 변경을 커밋·푸시한다.

| 단계 | 구현 범위 | 브라우저 확인 기준 | 상태 |
|---|---|---|---|
| 1 | 세 Nuxt 앱의 공통 기반, 오늘 할 일 등록·수정·완료, 우선순위 정렬, 모바일 목록 | 할 일을 추가하고 수정·완료할 수 있다. 높은 우선순위가 먼저 보이며 새로고침 후 유지된다. | 사용자 확인 완료 |
| 2 | 과거·오늘·미래 날짜의 일정, 실행 예정일 변경, 미완료 할 일 미루기 | 옮긴 작업이 새 날짜에 한 번만 보이고 제출 마감일이 유지된다. | 로컬 구현·검증 완료 |
| 3 | 프로젝트, 준비·진행·마감 단계의 텍스트 자료, 작업 연결 | 두 화면에서 같은 작업 상태를 확인하고 프로젝트 없이도 일정을 등록한다. | 로컬 구현·검증 완료 |
| 4 | Supabase 로그인, 사용자별 DB 저장, RLS, 시간대 설정 | 계정 간 자료가 격리되고 세 시안에서 같은 계정의 자료를 조회한다. | 코드·SQL 준비, 실제 계정 연결 검증 대기 |
| 5 | 내일 웹 알림, 세 시안 마무리, Vercel 배포 | 다음 날의 최신 일정 요약과 세 배포 주소를 확인한다. | 웹 알림 구현, Vercel 계정 연결·배포 대기 |

## 1단계의 임시 저장

로그인·DB 연결 전이므로 오늘 할 일은 현재 브라우저에만 저장한다. 계정 간 동기화나 서버 저장으로 표시하지 않는다. 세 시안은 기본 화면을 공유하며, 캘린더와 프로젝트 전용 구성은 해당 단계에서 연결한다. 이전에 작성된 후속 기능 코드는 현재 시작 화면에 연결하지 않는다.

동일 우선순위는 생성 순서로 정렬한다. 실행 예정일과 제출 마감일은 별도 필드이며, 1단계에서 실행 예정일은 오늘로 고정한다. 이메일 예약 발송과 홈 위젯은 앞서 합의한 웹 MVP 범위에 포함하지 않으며, 별도 요청과 설정 결정 후 진행한다.

## 확인 방법

- `npm run dev:feed`: http://localhost:3000
- `npm run dev:calendar`: http://localhost:3001
- `npm run dev:workspace`: http://localhost:3002
- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`: 자동 검사.

각 앱의 브라우저 저장은 접속 주소별로 분리된다. 4단계에서 Supabase 계정 데이터 공유를 연결한다. 브라우저 저장소를 지우면 임시 자료도 삭제된다.

## 1단계 검증 결과 (2026-11-19)

- 자동 테스트 5개, 세 앱 타입 검사, 세 앱 정적 빌드 통과.
- 브라우저에서 등록, 수정, 우선순위 정렬, 완료·완료 취소 확인.
- 새로고침 후 이름 수정, 마감일, 완료 상태 유지 확인.
- 모바일 390px 및 데스크톱 1440px에서 가로 넘침 없음.
- 확인 주소: http://localhost:3000
- 검증용 할 일 2개는 이름 앞에 `확인용 ·`으로 표시했다.
- 사용자가 1단계를 확인했다. 확인한 1단계만 커밋·푸시하며 다음 단계는 별도 요청 후 진행한다.

## 추가 승인된 화면 변경

- 서비스 이름과 코드 기반 로고를 CareerTrack으로 변경했다.
- 큰 메뉴는 홈 / 오늘 할 일 / 취업 관리다. 날짜별 일정은 홈 달력에서 접근한다.
- 홈에만 월별·주간 달력을 표시하며, 날짜 칸을 누르면 바로 해당 날짜 일정이 열린다. 별도의 날짜 열기 버튼은 제거했다.
- 홈의 상단 위치 표시는 홈 하나만 표시한다.
- 분류에 직접 입력(최대 40자)을 추가하고 저장·필터·DB 제약 조건에 반영했다.
- 별도 브리핑 메뉴와 사이드 카드 대신 상단 알림 버튼에서 내일 요약을 확인한다.

## 2~5단계 검증 및 남은 연결

- 자동 검사: 날짜·정렬·브리핑, 기존 자료 이전, 손상 자료 보호, 탭 간 저장, 사용자 소유권, 로그인 만료 중 조회 결과 차단, 직접 입력 분류, 월별·주간 범위 계산.
- 브라우저: 지난 날짜 등록 → 프로젝트 자료 연결 → 다른 날짜로 미루기 → 마감일·연결 유지 → 완료 상태 동기화 확인.
- 브라우저: 월별 42칸 / 주간 7칸, 날짜 직접 열기, 분류 직접 입력 및 필터, 상단 알림, 오늘 할 일 화면의 달력 제거 확인.
- 실제 Supabase DB에 마이그레이션과 RLS SQL 검증문은 아직 실행하지 않았다. 가입·이메일·다른 기기 저장은 실제 계정 연결 후 확인해야 한다.
- Vercel·Supabase 웹 로그인 화면까지 확인했으며, 실제 로그인과 배포 주소는 확인되지 않았다. 웹 대시보드 연결 방법은 SETUP.md에 기록했다.
- 계정 연결과 사용자 최종 확인 전에는 4·5단계의 실서비스 검증 완료로 표시하지 않는다. 새로운 커밋·푸시는 하지 않았다.

## 오늘 할 일 보드 변경

사용자 요청으로 오늘 할 일을 할 일 / 진행 중 / 완료 3열로 변경했다. PC에서는 기본 브라우저 드래그로 이동하고, 모바일·키보드에서는 수정창의 상태 선택을 사용한다. 완료 체크는 유지한다. 기존 완료 자료는 완료 열에 표시하며, 상태를 변경해도 같은 작업 ID·마감일·프로젝트 연결을 보존한다. DB에는 세 번째 마이그레이션으로 상태와 완료 여부의 일치 조건을 추가했다.

브라우저에서 상태 선택 및 드래그 이동을 확인했다. 자동 테스트는 총 26개이며, 기존 자료의 상태 변환·진행 중·완료·완료 취소 및 상태 불일치 거부를 포함한다. 현재 최종 브라우저 확인은 데스크톱에서 수행했으며, 실제 모바일 기기 검증은 남아 있다.

## 추가 사용자 요청: 시간표·항목 마감일·휴지통

- 홈의 고정 시간표는 기본적으로 꺼져 있는 선택 기능이다. 요일·시작/종료 시간·활동을 등록하고, 주간 시간 격자에서 블록을 눌러 수정한다. 겹치는 활동은 나란히 표시한다. 모바일에서는 선택한 요일의 시간표를 표시한다. 할 일을 자동 생성하지 않는다.
- 기업 프로젝트의 각 항목은 개별 마감일을 가진다. 자소서 마감 이후에 인적성·면접 마감일을 지정할 수 있고, 전체 지원 마감일과 별도로 관리하며, 연결된 대표 작업의 실행일·마감일을 오늘 할 일과 달력에서 함께 사용한다.
- 할 일 카드의 연필 옆에 휴지통 아이콘을 표시하고 메뉴 닫기 항목은 제거했다. 삭제는 복원 가능한 휴지통 이동이다. 하단 휴지통에서 원래 날짜·상태·프로젝트 연결을 유지해 복원한다. 영구 삭제 기능은 추가하지 않았다.
- 친구 맺기·서로의 워크스페이스 방문은 사용자 동의에 따라 후순위다. 개인 저장 안정화와 공개 범위 결정 후 별도로 다룬다.
- 메뉴 계층은 홈 / 오늘 할 일 / 기업별 지원 프로젝트를 담는 취업 관리로 유지한다. 프로젝트 관리 아래에 다시 취업 관리 계층을 만들지 않는다.
- 추가 DB 변경은 004(시간표), 005(항목 마감일), 006(휴지통) 마이그레이션에 있다. 실제 Supabase 적용은 대기 상태다.


## 현재 구현 반영 (2026-11-19)

- 기업별 상세 페이지의 일정·할 일 / 자료 보관함을 구현했다. 텍스트·링크·파일 첨부가 가능하다. 체험 모드 파일은 IndexedDB, 실제 계정 파일은 비공개 Supabase Storage를 사용한다.
- 로컬 브라우저에서 파일 업로드·다운로드·새로고침 후 자료 유지 확인을 수행했다. 실제 계정 Storage·RLS는 미검증이다.
- 홈은 완료 작업까지 한 목록으로 보여주며, 완료한 일은 아래로 정렬하고 취소선을 표시한다.
- 홈 달력에 주간 우선순위 선택 입력을 추가했다. 기본 접힘, 주별 최대 3개이며 기존 월간 자료는 유지한다. 주별 저장에는 011 마이그레이션이 필요하다.
- 종료 프로젝트는 삭제하지 않고 보관하며 다시 진행 상태로 열 수 있다.
- OpenRouter 키는 비공개 설정에만 보관하며 AI 호출은 연결하지 않았다. 그로블도 설정 예시·연결 안내만 준비했다.
- 사용자가 현재까지 개발분의 GitHub 업로드와 Vercel 배포를 요청했다. 이번 요청은 해당 변경의 커밋·푸시 승인을 포함한다.
- 자동 테스트 40개, 린트, 세 앱 타입 검사 통과. 실제 Supabase 가입·사용자 격리·시안 간 동기화와 최종 모바일 실기기 검증은 남아 있다.
