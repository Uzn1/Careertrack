# PRD 구현 단계

기준: 저장소 루트 `PRD.md`. 사용자 지정 기술은 Nuxt 4·Vue·TypeScript·Tailwind CSS, 데이터 저장은 Supabase, 배포는 Vercel이다. 각 단계가 끝나면 멈추고 사용자의 브라우저 확인을 기다린다. 확인 후 해당 단계만 커밋·푸시한다.

| 단계 | 구현 범위 | 브라우저 확인 기준 | 상태 |
|---|---|---|---|
| 1 | 세 Nuxt 앱의 공통 기반, 오늘 할 일 등록·수정·완료, 우선순위 정렬, 모바일 목록 | 할 일을 추가하고 수정·완료할 수 있다. 높은 우선순위가 먼저 보이며 새로고침 후 유지된다. | 사용자 확인 완료 |
| 2 | 과거·오늘·미래 날짜의 일정, 실행 예정일 변경, 미완료 할 일 미루기 | 옮긴 작업이 새 날짜에 한 번만 보이고 제출 마감일이 유지된다. | 대기 |
| 3 | 프로젝트, 준비·진행·마감 단계의 텍스트 자료, 작업 연결 | 두 화면에서 같은 작업 상태를 확인하고 프로젝트 없이도 일정을 등록한다. | 대기 |
| 4 | Supabase 로그인, 사용자별 DB 저장, RLS, 시간대 설정 | 계정 간 자료가 격리되고 세 시안에서 같은 계정의 자료를 조회한다. | 대기 |
| 5 | 내일 웹 브리핑, 세 시안 마무리, Vercel 배포 | 다음 날의 최신 일정 요약과 세 배포 주소를 확인한다. | 대기 |

## 1단계의 임시 저장

로그인·DB 연결 전이므로 오늘 할 일은 현재 브라우저에만 저장한다. 계정 간 동기화나 서버 저장으로 표시하지 않는다. 세 시안은 기본 화면을 공유하며, 캘린더와 프로젝트 전용 구성은 해당 단계에서 연결한다. 이전에 작성된 후속 기능 코드는 현재 시작 화면에 연결하지 않는다.

동일 우선순위는 생성 순서로 정렬한다. 실행 예정일과 제출 마감일은 별도 필드이며, 1단계에서 실행 예정일은 오늘로 고정한다. 이메일 예약 발송과 홈 위젯은 앞서 합의한 웹 MVP 범위에 포함하지 않으며, 별도 요청과 설정 결정 후 진행한다.

## 확인 방법

- `npm run dev:feed`: http://localhost:3000
- `npm run dev:calendar`: http://localhost:3001
- `npm run dev:workspace`: http://localhost:3002
- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`: 자동 검사.

각 앱의 브라우저 저장은 접속 주소별로 분리된다. 4단계에서 Supabase 계정 데이터 공유를 연결한다. 브라우저 저장소를 지우면 임시 자료도 삭제된다.

## 1단계 검증 결과 (2026-11-19)

- 자동 테스트 5개, 세 앱 타입 검사, 세 앱 정적 빌드 통과.

- 새로고침 후 이름 수정, 마감일, 완료 상태 유지 확인.
- 모바일 390px 및 데스크톱 1440px에서 가로 넘침 없음.
- 확인 주소: http://localhost:3000
- 검증용 할 일 2개는 이름 앞에 `확인용 ·`으로 표시했다.
- 사용자가 1단계를 확인했다. 확인한 1단계만 커밋·푸시하며 다음 단계는 별도 요청 후 진행한다.
