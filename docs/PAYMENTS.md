# 그로블 결제 연결 준비

## 현재 상태

사용자 결정에 따라 **연결 준비만** 진행합니다. 상품·가격·유료 범위는 미정입니다. 결제 버튼, 결제 수신 서버, 이용 권한 변경은 아직 구현하지 않았습니다. 설정 값을 입력해도 결제가 활성화되지 않습니다.

## 설정 파일

프로젝트 루트 `.env`에 다음 빈 항목을 마련했습니다. 지금은 비워 두어도 됩니다.

| 항목 | 나중에 넣을 값 |
|---|---|
| `GROBLE_CHECKOUT_URL` | 그로블에서 만든 상품의 결제창 주소 |
| `GROBLE_WEBHOOK_SECRET` | 결제 결과 알림의 진위를 확인하는 비밀 값 |

비밀 값은 대화·GitHub에 올리지 않습니다. `NUXT_PUBLIC_` 접두사를 붙이지 않습니다. `OPENROUTER_API_KEY`는 AI용이며 그로블 결제에 사용하지 않습니다.

## 실제 연결 순서

1. 가격·단건 또는 구독·유료 기능·환불 기준을 결정합니다.
2. 그로블 웹 대시보드에서 상품과 결제창을 만들고, 배포한 HTTPS 진입·복귀 주소를 지정합니다.
3. Supabase Edge Function 등 서버에 결제 요청과 결과 알림 수신 기능을 구현합니다. 현재 Vercel 배포는 정적 화면이므로 비밀 처리를 웹 화면에 넣지 않습니다.
4. 서버에서 무작위 주문 참조값을 만들고 로그인 사용자와 연결해 보관합니다. 결제창의 `ref`에는 개인정보를 넣지 않습니다.
5. 그로블의 연동 화면에 수신 서버 주소를 등록하고, 발급된 비밀 값을 해당 서버의 비밀 설정에 직접 저장합니다. 로컬 `.env`만 수정하면 배포 서버에 전달되지 않습니다.
6. 아래 검증을 마친 뒤 결제 버튼과 이용 권한을 연결합니다.

## 구현 시 확인할 사항

- 원본 요청과 타임스탬프로 서명을 검증하고, 허용 시간 범위 밖의 알림을 거부합니다.
- 중복 알림은 한 번만 반영하고, 저장 성공 후 응답합니다.
- 결제 주문과 회원을 대조합니다. 복귀 페이지 방문만으로 결제 완료로 처리하지 않습니다.
- 완료뿐 아니라 취소·환불도 반영합니다. 구독을 선택하면 갱신 실패·해지 기준도 정합니다.
- 정상·위조·중복 알림과 다른 회원 주문 접근을 검사합니다. 실제 검증 전에는 결제 연동 완료로 보고하지 않습니다.
